# Migrations

Numbered SQL files, applied in order (`0001_core.sql`, `0002_...sql`). Never edit
a migration that has already run on a shared database: add a new one.

| File | What it adds |
| ---- | ------------ |
| `0001_core.sql` | Fields, skills, synonyms, schools, profiles, user skills, recovery tables, listings, listing skills. Row-level security on every table. |
| `0002_accounts.sql` | Age confirmation and onboarding date on profiles; profiles created by the server only, and users may update only their own profile fields (never the username); `user_settings`; `rate_limits` with `take_rate_limit()`; `set_my_skills()` and `my_recovery()`. |
| `0003_places.sql` | `geocode_cache`: map lookups of typed places (found or not), server only. |
| `0004_quest_log.sql` | `applications` (the quest log; `confirmed_at` and `last_clicked_at` are server-only) and `click_logs` (Apply clicks, no IP, unlinked on account deletion). |
| `0005_game.sql` | `exp_events` (one row per reward, unique per action, server-written only), `user_badges`, `activity_flags` (admin review), and `leaderboard_entries()` (server only: Full Quest players who aren't hidden, plus you). |
| `0006_learning.sql` | `skill_resources` (public, seeded), `resource_opens` (server only), `tips_progress` (own read, server writes), `ai_usage` (server only, the 5-a-day cap), and two new EXP kinds (`resource`, `cover_letter`). |
| `0007_imports.sql` | One row per source posting (`source`, `source_ref`), `import_runs` (the daily job's log, server only), and `expire_listings()` (hides past-deadline and stale aggregator listings, server only). |
| `0008_companies.sql` | `companies` (one per company sign-in user; own row readable, no direct writes), listing ownership (`company_id`), the draft → published → closed `status` (drafts never public; a published listing must be complete), `start_date`, and the server-only `admins`, `admin_audit`, and `reports` tables. Flags get `window_start`/`window_end` so "Reverse EXP" undoes only that hour. |
| `0009_retention.sql` | `purge_old_data()` (server only): the daily job deletes old Apply clicks, resolved reports and flags, old admin log entries, and old import logs, on the periods in `src/lib/retention.ts`. Open reports and flags are never deleted. The admin log also records CSV imports. |
| `0010_listing_updated_at.sql` | `updated_at` on listings (with the usual trigger), which the company dashboard shows as "last edited". |

`../seed.sql` is generated by `npm run db:seed` from `src/lib/catalog`. Its
listings are fictional samples for **local or dev projects only**.

## Tested without a project

`tests/db/database.test.ts` runs every migration plus the seed in PGlite
(Postgres compiled to WebAssembly) with a small Supabase shim
(`tests/db/supabase-shim.sql`). It checks the constraints and the row-level
security as each API role (`anon`, `authenticated`) would see them. It runs
as part of `npm test`.
